# Локальный Harbor

Harbor хранит образы контейнеров. В этом задании вы запустите Harbor v2.14.0
и проверите образ на уязвимости с помощью Trivy.

## Подготовьте компьютер

Нужны Docker с Linux-контейнерами, Docker Compose v2, Bash и curl.
Скрипты поддерживают плагин `docker compose` и отдельную команду `docker-compose` версии v2.
Они выбирают доступную команду автоматически. Compose v1 не проверен.
Если используете `docker-compose`, заменяйте ею `docker compose` в командах ниже.

На Linux используйте Docker Engine. На macOS можно использовать Docker Desktop или Colima.
На Windows используйте Docker Desktop с WSL2. Запускайте скрипты в WSL2.
Храните репозиторий в файловой системе WSL.

Выделите Docker 8 ГиБ памяти. Оставьте минимум 40 ГБ свободного места.
Нужен интернет для загрузки образов и базы уязвимостей.
Стенд использует `linux/amd64`. На Apple Silicon нужна эмуляция этой архитектуры.
Проверьте запуск до занятия.

### Настройте Colima на macOS

Для нового или остановленного профиля выполните:

```bash
colima start --memory 8
docker context use colima
docker info --format 'Memory available to Docker: {{.MemTotal}} bytes'
```

Последняя команда показывает память среды Docker в байтах.
Значение должно быть близко к 8 ГиБ: 8 589 934 592 байтам.
Не ориентируйтесь на общий объём памяти компьютера.

Если Colima уже работает с меньшим объёмом памяти, перезапустите её.
Остановка прервёт работу всех контейнеров этого профиля:

```bash
colima stop
colima start --memory 8
```

Профиль и каталог `harbor/runtime/` сохраняются.
В предыдущем запуске с 2 ГиБ Trivy не смог открыть базу уязвимостей.
Он вернул ошибку `failed to open db: cannot allocate memory`.
[Настройка ресурсов Colima](https://github.com/abiosoft/colima#customizing-the-vm).

## Подготовьте и запустите Harbor

**Перед первым ручным запуском Compose обязательно выполните `bash prepare.sh`.**
Без подготовки отсутствуют файлы конфигурации и ключи, которые нужны сервисам.

1. Из корня репозитория перейдите в каталог Harbor:

   ```bash
   cd harbor
   ```

2. Если хотите изменить учебные пароли, создайте `.env` и отредактируйте его до подготовки:

   ```bash
   cp .env.example .env
   ```

   Этот шаг нужен, только если `.env` ещё нет и вы хотите задать свои значения.
   Иначе `prepare.sh` сам скопирует `.env.example` в `.env`.
   Не перезаписывайте существующий `.env`.
   Смена переменной после инициализации БД не меняет пароль администратора.

3. Подготовьте конфигурацию:

   ```bash
   bash prepare.sh
   ```

   Скрипт запускает официальный образ `goharbor/prepare:v2.14.0` с `--with-trivy`.
   Он создаёт конфигурацию и внутренние ключи подписи в каталоге `runtime/`.
   Внешние TLS-сертификаты для этого стенда не нужны.
   Дождитесь успешного завершения команды.

4. Запустите сервисы:

   ```bash
   docker compose up -d
   docker compose ps
   ```

5. Проверьте готовность:

   ```bash
   curl -fsS http://localhost:8081/api/v2.0/health
   ```

   Первый запуск может занять несколько минут. Ожидается общий статус `healthy`.
   Если сервисы ещё запускаются, подождите и повторите запрос.
   Запущенный контейнер сам по себе не подтверждает готовность Harbor.

Вместо шагов 3 и 4 можно выполнить `bash start.sh`.
Этот скрипт сначала вызывает `prepare.sh`, затем запускает сервисы.
После него также проверьте готовность запросом из шага 5.

Откройте [портал Harbor](http://localhost:8081).
Войдите как `admin`. Учебный пароль из `.env.example`: `HarborLab12345!`.
Если вы задали другой пароль до первого запуска, используйте его.

Стенд запускает 10 сервисов из официальных образов `goharbor/*` версии v2.14.0.
HTTP доступен только на `127.0.0.1`. Используйте стенд на одном компьютере.
Не открывайте его в сеть. Не храните в нём рабочие секреты.
Для общего реестра образов нужен HTTPS. Не используйте учебные пароли в других средах.

[Официальный prepare](https://github.com/goharbor/harbor/blob/v2.14.0/make/prepare),
[шаблон Compose](https://github.com/goharbor/harbor/blob/v2.14.0/make/photon/prepare/templates/docker_compose/docker-compose.yml.jinja).

## Разрешите локальный реестр с HTTP

Если Docker возвращает `server gave HTTP response to HTTPS client`,
добавьте `localhost:8081` в список `insecure-registries` настроек Docker daemon.
Сохраните остальные поля JSON и существующие элементы списка.
Ниже показано только нужное поле:

```json
{"insecure-registries": ["localhost:8081"]}
```

В Docker Desktop откройте настройки Docker Engine. Измените поле и нажмите **Apply & Restart**.
На Linux измените поле в `/etc/docker/daemon.json` и перезапустите Docker.
Перезапуск затрагивает другие контейнеры. Выполните настройку до практики.
Не заменяйте весь существующий файл приведённым примером.
[Настройка dockerd](https://docs.docker.com/reference/cli/dockerd/#insecure-registries).

## Загрузите базу Trivy

Выполните этот шаг после получения статуса `healthy` и до первого сканирования.
Все команды выполняйте из каталога `harbor/`.

1. Загрузите базу уязвимостей:

   ```bash
   docker compose exec -T trivy-adapter \
     trivy image --download-db-only \
     --timeout 15m \
     --cache-dir /home/scanner/.cache/trivy
   ```

   Дождитесь завершения с кодом 0.

2. Проверьте файл базы и метаданные:

   ```bash
   docker compose exec -T trivy-adapter sh -c \
     'test -s /home/scanner/.cache/trivy/db/trivy.db && cat /home/scanner/.cache/trivy/db/metadata.json'
   ```

   Ожидается JSON с датами обновления базы и код завершения 0.

При медленной загрузке сканирование может вернуть `context deadline exceeded`.
Стандартный таймаут сканирования составляет 5 минут.
Для отдельной загрузки выше задано 15 минут.
Если этого недостаточно, проверьте соединение и повторите команду с большим `--timeout`.
Если сканирование уже завершилось ошибкой загрузки базы, нажмите **Scan** после загрузки.

Кэш находится в `harbor/runtime/data/trivy-adapter/trivy`.
Он сохраняется после обычного перезапуска. Не удаляйте его перед занятием.
Trivy использует сохранённую базу и обновляет её при необходимости.
[Управление базой Trivy](https://trivy.dev/docs/v0.66/guide/configuration/db/).

## Загрузите и проверьте образ

Сначала соберите образ `club-demo:1.0` по [инструкции приложения](../app/README.md).

1. В портале Harbor создайте приватный проект `club`.
2. В настройках проекта **Configuration** включите **Automatically scan images on push**.
3. При необходимости задайте квоту проекта и создайте robot account с правами push/pull.
4. Войдите в реестр и загрузите образ. Эти команды можно выполнять из любого каталога:

   ```bash
   docker login localhost:8081
   docker tag club-demo:1.0 localhost:8081/club/counter:1.0
   docker push localhost:8081/club/counter:1.0
   docker pull localhost:8081/club/counter:1.0
   ```

5. Откройте артефакт в `club/counter`. Дождитесь завершённого отчёта сканирования.
6. Если отчёт содержит CVE, разберите одну запись: пакет, версию, критичность и доступное исправление.

CVE — идентификатор известной уязвимости.
Число уязвимостей зависит от образа и текущей базы.
Ошибка сканирования не означает, что уязвимостей нет.
[Настройки проекта](https://goharbor.io/docs/2.14.0/working-with-projects/project-configuration/),
[сканирование](https://goharbor.io/docs/2.14.0/administration/vulnerability-scanning/).

## Остановите и повторно запустите стенд

Из каталога `harbor/` выполните:

```bash
docker compose down
docker compose up -d
curl -fsS http://localhost:8081/api/v2.0/health
```

После получения статуса `healthy` проверьте доступ к сохранённому образу:

```bash
docker pull localhost:8081/club/counter:1.0
```

Данные хранятся в каталогах компьютера, подключённых к контейнерам:

| Каталог внутри `harbor/` | Содержимое |
| --- | --- |
| `runtime/data/registry` | Данные образов |
| `runtime/data/database` | Метаданные Harbor |
| `runtime/common/config` | Конфигурация сервисов |
| `runtime/data/secret` | Ключи |

Не удаляйте и не перемещайте `runtime/` после подготовки конфигурации.
Даже `docker compose down -v` не удаляет эти файлы: стенд использует bind mounts.
Полное удаление `runtime/` уничтожит образы, БД и ключи.
Каталог `runtime/` и файл `.env` исключены из Git. Не добавляйте их в репозиторий.

Правила хранения (retention) задают удаление артефактов.
Сборка мусора (garbage collection) освобождает данные, которые больше не используются.
Перед удалением проверьте результат через **dry run** соответствующей операции.
[Сборка мусора](https://goharbor.io/docs/2.14.0/administration/garbage-collection/).

## Если возникла ошибка

| Признак | Что проверить |
| --- | --- |
| Compose сообщает об отсутствующем файле конфигурации | Убедитесь, что `bash prepare.sh` завершился успешно до `docker compose up -d`. |
| На Mac недоступен каталог bind mount | Проверьте **File Sharing** в Docker Desktop. |
| Trivy не загружает базу | Проверьте интернет и журнал: `docker compose logs trivy-adapter`. |
| Trivy возвращает `cannot allocate memory` | Проверьте память Docker. Для Colima задайте 8 ГиБ, как указано выше. |
| Порт 8081 или 1514 занят | Остановите другой учебный Harbor или согласованно измените конфигурацию до запуска. |

До занятия проверьте полный сценарий на каждой используемой платформе.
Особенно проверьте Apple Silicon и Windows/WSL2.
Готовность подтверждают запуск, загрузка образа и завершённый отчёт Trivy.
Проверки синтаксиса конфигурации для этого недостаточно.
