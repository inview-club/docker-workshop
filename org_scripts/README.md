# Скрипты для проведения практики

Каждый скрипт выполняет одно задание от подготовки до проверки результата.
Запускайте задания по одному. Скрипты работают из любого текущего каталога.
Пути в примерах ниже указаны относительно корня репозитория.

## Что нужно заранее

Установите Docker с Linux-контейнерами, Docker Compose v2, Bash, curl, Python 3 и OpenSSL.
Скрипты не устанавливают Docker, не запускают VM и не меняют настройки Docker daemon.
На Windows используйте WSL2. На macOS с Colima выделите 8 ГиБ памяти:

```bash
colima start --memory 8
docker context use colima
```

Для Harbor оставьте минимум 40 ГБ свободного места.
Используется локальный учебный стенд из [harbor/](../harbor/README.md).
Доступ в интернет нужен для первоначальной подготовки образов, зависимостей и базы Trivy.

Перед запуском освободите порт 8080 от других учебных приложений.
Harbor использует порты 8081 и 1514.
Скрипты не останавливают посторонние контейнеры для освобождения портов.

## Базовый трек

| Скрипт | Что он делает |
| --- | --- |
| `basic/01-nginx.sh` | Запускает nginx, проверяет HTTP, журнал и конфигурацию. Останавливает и удаляет контейнер. Проверяет, что образ остался. |
| `basic/02-dockerfile.sh` | Собирает приложение, проверяет UID 10001 и HTTP. Меняет временную копию `app.py` и повторяет сборку для демонстрации кэша. |
| `basic/03-compose.sh` | Запускает приложение с Redis. Пересоздаёт контейнеры и проверяет, что счётчик сохранился. |
| `basic/04-harbor.sh` | Выполняет `prepare.sh`, запускает Harbor, ждёт `healthy`, загружает базу Trivy. Создаёт приватный проект `club`, выполняет push/pull и дожидается отчёта сканирования. |

Например:

```bash
bash org_scripts/basic/01-nginx.sh
bash org_scripts/basic/04-harbor.sh
```

Harbor-скрипт сам собирает `club-demo:1.0`, если это требуется для задания.
Предварительно проходить задания 2 и 3 не обязательно.
Он использует пароль администратора из `harbor/.env`.
Если файл ещё не создан, `prepare.sh` создаёт его из `.env.example`.
Если пароль в работающем Harbor отличается от `.env`, передайте действующий пароль
через переменную окружения `HARBOR_ADMIN_PASSWORD` без записи значения в историю команд.
Скрипт не сбрасывает пароль администратора.

При создании проекта `club` задаётся квота 10 ГиБ.
Если приватный проект уже существует, скрипт сохраняет его квоту и включает автоматическое сканирование.
Если существующий проект публичный, скрипт останавливается и не меняет права доступа.
Пароль для Docker login передаётся через стандартный ввод.
Временный профиль авторизации Docker удаляется после push/pull, в том числе при ошибке.

Harbor остаётся работать для просмотра образа и отчёта: [открыть портал](http://localhost:8081).
Скрипт ждёт готовности до 10 минут и отчёта сканирования до 30 минут.
Ошибка или истечение срока ожидания приводит к ненулевому коду завершения.
Если push возвращает `server gave HTTP response to HTTPS client`,
выполните [настройку локального HTTP-реестра](../harbor/README.md#разрешите-локальный-реестр-с-http)
и повторите скрипт. Настройки Docker daemon автоматически не изменяются.

## Дополнительный трек

| Скрипт | Что он делает |
| --- | --- |
| `advanced/01-cgroups.sh` | Показывает namespaces, создаёт нагрузку CPU и проверяет лимиты cgroups v2. |
| `advanced/02-multistage.sh` | Собирает этап `build` и итоговый образ. Проверяет HTTP и UID, показывает размеры образов. |
| `advanced/03-hadolint.sh` | Проверяет хороший Dockerfile и ожидаемые ошибки плохого. Затем проверяет Dockerfile из задания multistage. |
| `advanced/04-openssl.sh` | При необходимости собирает образ. Экспортирует его, создаёт зашифрованный ключ, подписывает архив и проверяет подпись. Обнаруживает изменение копии архива. |
| `advanced/05-volumes.sh` | Проверяет копирование файла из образа в пустой том, запись из первого контейнера и чтение из второго. |

Например:

```bash
bash org_scripts/advanced/04-openssl.sh
```

В задании OpenSSL случайный пароль создаётся автоматически и живёт только в окружении процесса.
Это позволяет выполнить демонстрацию без ручного ввода пароля на каждом шаге.
Ключи и архивы временные. Для ручной работы с сохранением ключа используйте
[отдельную инструкцию OpenSSL](../advanced/openssl/README.md).

## Повторный запуск и очистка

Уже скачанные образы используются повторно. Скрипты загружают только отсутствующие образы.
Сборка выполняется без `--pull` и без отключения кэша.
Скрипты не выполняют `docker rmi`, `image prune`, `system prune` или очистку кэша сборки.

После короткого задания удаляются его контейнеры и временные файлы.
Изменения `app.py` выполняются в копии, исходный файл остаётся прежним.
Образы `club-demo:1.0`, `club-demo:cache-demo`, `club-advanced:1.0`,
`club-advanced-build:1.0` и `club-volume-demo:1.0` сохраняются.
Повторная сборка обновляет эти учебные теги.

Compose использует отдельный проект `org-workshop-app`.
Его контейнеры останавливаются после проверки, том Redis сохраняется.
Задание с томами удаляет только свой временный том `org-workshop-volumes`.
Именованные контейнеры и том проверяются по метке `org.inview.workshop=org-scripts`.
При совпадении имени с чужим ресурсом скрипт отказывается его удалять.

Harbor использует существующий проект Compose `harbor-lab`.
Его контейнеры и каталог `harbor/runtime/` сохраняются.
Скрипт повторно использует проект `club` и обновляет учебный тег `club/counter:1.0`.
Не используйте этот проект для посторонних образов или секретов.

Одновременный запуск заданий блокируется через `org_scripts/.state/task.lock`.
После обычного завершения, ошибки, `Ctrl+C` или `SIGTERM` блокировка снимается.
После аварийного завершения через `SIGKILL` сначала убедитесь, что процесс больше не работает.
Затем удалите только пустой каталог блокировки:

```bash
rmdir org_scripts/.state/task.lock
```

## Подготовка к аудитории с плохим интернетом

До занятия выполните все нужные скрипты на каждом компьютере с хорошим интернетом.
Одной загрузки базовых образов недостаточно: сборке приложения нужны Python-пакеты,
а Harbor нужна база Trivy.
Один успешный проход сохраняет образы, зависимости в слоях сборки и базу сканера.
Не очищайте образы, кэш сборки, том Redis и `harbor/runtime/` перед занятием.

После подготовки повторите задания без загрузки образов:

```bash
WORKSHOP_OFFLINE=1 bash org_scripts/basic/01-nginx.sh
WORKSHOP_OFFLINE=1 bash org_scripts/basic/04-harbor.sh
```

В этом режиме отсутствующий базовый образ вызывает ошибку вместо загрузки из внешнего реестра.
Команды push/pull в задании Harbor по-прежнему обращаются к реестру на этом компьютере.
Для шагов сборки отключается сеть внутри команд `RUN`.
Если отсутствуют нужные слои кэша, сборка может завершиться ошибкой.
Подготовьте её при доступном интернете.

Harbor использует сохранённую базу Trivy. Обновления базы, Java DB и сетевой анализ зависимостей отключаются.
Результат сканирования относится к сохранённой базе и не учитывает более новые сведения об уязвимостях.
Убедитесь до занятия, что база уже загружена.
Режим меняет параметры только локального сервиса `trivy-adapter`.
Обычный повторный запуск Harbor-скрипта без `WORKSHOP_OFFLINE=1` возвращает сетевые обновления.

## Проверка скриптов

Из корня репозитория выполните:

```bash
python3 -m unittest discover -s org_scripts/tests -v
```

Проверки используют подставные Docker и Harbor.
Они проверяют повторный запуск, сохранение образов и данных, отказ от удаления чужого контейнера,
очистку после ошибки, ожидание нового отчёта Trivy и обработку ошибок сканирования.
В проверке подписи используется настоящий OpenSSL и небольшой тестовый архив.
Эти проверки не подтверждают живой запуск Docker или Harbor на компьютере участника.

API-запросы соответствуют [спецификации Harbor v2.14.0](https://github.com/goharbor/harbor/blob/v2.14.0/api/v2.0/swagger.yaml).
