# Проверка Dockerfile с Hadolint

Hadolint проверяет правила написания Dockerfile.
В этом задании вы сравните файл с ошибками и исправленный файл.
Нужен запущенный Docker с Linux-контейнерами и доступ в интернет для загрузки образа Hadolint.

## Проверьте два примера

Из корня репозитория перейдите в `advanced/`:

```bash
cd advanced
```

1. Проверьте файл с намеренными ошибками:

   ```bash
   bash hadolint/lint.sh Dockerfile.bad
   ```

   Ожидаются ненулевой код завершения и сообщения из таблицы ниже.

2. Проверьте исправленный файл:

   ```bash
   bash hadolint/lint.sh Dockerfile.good
   ```

   Ожидается код завершения 0.

| Правило | Причина сообщения | Как исправить |
| --- | --- | --- |
| DL3007 | Указан образ `alpine:latest` | Выберите версию базового образа. |
| DL3018 | Команда `apk add curl` не указывает версию пакета | Укажите подходящую версию, если пакет нужен. |
| DL3019 | Команда `apk add` сохраняет кэш | Добавьте `--no-cache`. |
| DL3025 | Команда `CMD echo hello` запускается через командную оболочку | Используйте форму `CMD ["echo", "hello"]`. |

В исправленном файле указан тег версии Alpine и форма `CMD` с массивом аргументов.
Установка curl удалена: для вывода строки `hello` этот пакет не нужен.
Поэтому сообщения о командах `apk` исчезают после удаления зависимости.
Если вашему приложению нужен пакет, исправьте обе настройки `apk` из таблицы.

Указание тега версии не гарантирует неизменность содержимого образа.
Для фиксации содержимого используют digest — идентификатор содержимого образа.
Успешная проверка Hadolint не заменяет тесты приложения и поиск уязвимостей.

## Проверьте Dockerfile из другого задания

Из `advanced/` выполните:

```bash
docker run --rm -i ghcr.io/hadolint/hadolint:v2.15.1 < multistage/Dockerfile
```

Файл передаётся через стандартный ввод. Подключать каталог компьютера к контейнеру не нужно.
Такой же способ использует скрипт `hadolint/lint.sh`.

[Описание правил Hadolint](https://github.com/hadolint/hadolint).
