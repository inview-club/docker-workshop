# Дополнительные задания по Docker

Вы проверите ограничения ресурсов, соберёте образ в несколько этапов,
проверите Dockerfile и сохраните данные в томе.
В конце вы подпишете архив образа с помощью OpenSSL.

Нужны запущенный Docker с Linux-контейнерами и Bash.
Для HTTP-запросов нужен curl. Для подписи архива нужен OpenSSL.
На Windows используйте WSL2.
Скрипты создают учебные образы и контейнеры в текущем контексте Docker.

Из корня репозитория перейдите в каталог заданий:

```bash
cd advanced
```

Каждый раздел ниже начинайте из `advanced/`.
Если команда меняет каталог, перед следующим разделом вернитесь в `advanced/`.

## 1. Проверьте изоляцию и ограничения ресурсов

Namespaces изолируют ресурсы, которые видят процессы контейнера.
Cgroups ограничивают ресурсы, которые процессы могут использовать.
Для этого задания нужны cgroups v2.

Запустите скрипт:

```bash
bash cgroups/demo.sh
```

Скрипт создаёт один контейнер с лимитами 0,5 CPU, 64 МиБ памяти и 64 PID.
Он читает `/proc/1/ns`, `cpu.max`, `memory.max` и `pids.max`.
Затем он создаёт нагрузку CPU на две секунды и выводит `cpu.stat`.

Для обычного Docker с cgroups v2 ожидаются такие значения:

| Файл | Значение | Значение ограничения |
| --- | --- | --- |
| `cpu.max` | `50000 100000` | 50 000 микросекунд CPU на период 100 000 микросекунд |
| `memory.max` | `67108864` | 64 МиБ памяти в байтах |
| `pids.max` | `64` | Не более 64 PID |

Идентификаторы namespaces и счётчики нагрузки зависят от запуска.
Поле `nr_throttled` показывает число периодов, когда контейнер исчерпал квоту CPU.

Скрипт не включает привилегированный режим и не использует пространство PID хоста.
Он не изменяет cgroups хоста. На cgroups v1 скрипт завершится с пояснением.
На macOS, Windows и Colima он читает файлы внутри Linux-среды Docker.

## 2. Соберите образ в несколько этапов

Сначала убедитесь, что порт 8080 свободен.

1. Перейдите в каталог примера и соберите образ:

   ```bash
   cd multistage
   docker build -t club-advanced:1.0 .
   ```

2. Запустите приложение и проверьте ответ:

   ```bash
   docker run --rm -d --name club-advanced -p 127.0.0.1:8080:8080 club-advanced:1.0
   curl http://127.0.0.1:8080/
   ```

   Ожидаемый ответ: `Hello from multistage! UID=10001`.

3. Остановите контейнер:

   ```bash
   docker stop club-advanced
   ```

   Параметр `--rm` удаляет контейнер после остановки.

4. Соберите образ этапа сборки и сравните размеры:

   ```bash
   docker build --target build -t club-advanced-build:1.0 .
   docker image inspect club-advanced-build:1.0 club-advanced:1.0 --format '{{index .RepoTags 0}} {{.Size}}'
   ```

   Размеры указаны в байтах. Они зависят от архитектуры и версий образов.

5. Вернитесь в `advanced/`:

   ```bash
   cd ..
   ```

Этап `build` содержит компилятор Go и исходный код.
В итоговый образ копируется только статический исполняемый файл.
Базовый образ `scratch` не содержит командной оболочки, набора сертификатов CA и средств отладки.
Пример принимает HTTP-запросы и не обращается к внешним HTTPS-сервисам.
Для рабочего приложения выбирайте базовый образ с учётом его зависимостей.
Go 1.24.6 указан как учебная версия. Для рабочего сервиса обновите его по правилам проекта.

## 3. Проверьте Dockerfile с Hadolint

Из `advanced/` выполните:

```bash
bash hadolint/lint.sh Dockerfile.good
bash hadolint/lint.sh Dockerfile.bad
```

Для хорошего примера ожидается код завершения 0.
Для плохого примера ожидаются ненулевой код и сообщения DL3007, DL3018, DL3019, DL3025.
Ошибки в плохом примере добавлены намеренно.
[Разбор ошибок и проверка другого Dockerfile](hadolint/README.md).

## 4. Проверьте сохранение данных в томе

Том (volume) хранит данные отдельно от контейнера.
Из `advanced/` выполните:

```bash
bash volumes/demo.sh
```

Скрипт собирает образ с файлом `/data/seed.txt` и создаёт том с уникальным именем.
Затем он выполняет три действия:

1. Подключает пустой том. Docker копирует в него `seed.txt` из образа.
2. Записывает `result.txt` из первого контейнера и удаляет контейнер.
3. Читает файл из второго контейнера. Том подключён только для чтения.

В выводе должна быть строка `written by container 1`.
Том остаётся после завершения скрипта.

Когда закончите проверку, скопируйте точную команду `docker volume rm ...` из вывода скрипта.
Она удалит созданный том и его данные.
Не используйте для этого задания общую команду `docker volume prune`.

## 5. Подпишите архив с помощью OpenSSL

Следуйте [инструкции подписи архива](openssl/README.md).
Используйте образ `club-advanced:1.0` из задания 2.
Реестр образов для этого задания не нужен.

Вы подпишете конкретный архив `docker save`.
Это не создаёт подпись OCI-образа в реестре.
Docker и Harbor не проверяют такую подпись автоматически.
Проверяйте архив вручную перед `docker load`.
