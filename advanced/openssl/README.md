# Локальная подпись архива образа

Вы сохраните образ в архив, подпишете архив и проверите подпись.
Затем вы измените копию архива и убедитесь, что проверка обнаруживает изменение.

Нужны Docker, OpenSSL и образ `club-advanced:1.0`.
Соберите его по [заданию со сборкой в несколько этапов](../README.md#2-соберите-образ-в-несколько-этапов).
Команды выполняйте по порядку в одном терминале.

## Сохраните образ в архив

Из корня репозитория перейдите в каталог задания:

```bash
cd advanced/openssl
```

Создайте отдельный каталог проверки и сохраните образ:

```bash
umask 077
demo_dir="demo-$(date +%Y%m%d%H%M%S)-$$"
mkdir "$demo_dir"
cd "$demo_dir"
docker save -o image.tar club-advanced:1.0
```

Команда `umask 077` ограничивает права на новые файлы.
Все следующие команды выполняйте из созданного каталога `demo-*`.

## Создайте ключи и подпишите архив

1. Создайте зашифрованный закрытый RSA-ключ:

   ```bash
   openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 \
     -aes-256-cbc -out signing.key
   ```

   OpenSSL попросит задать пароль ключа.
   Вводите пароль в приглашении. Не передавайте его в аргументах команды.

2. Сохраните открытый ключ:

   ```bash
   openssl pkey -in signing.key -pubout -out signing.pub
   ```

   Введите пароль закрытого ключа, когда OpenSSL его запросит.

3. Подпишите архив:

   ```bash
   openssl dgst -sha256 -sign signing.key -out image.tar.sig image.tar
   ```

   OpenSSL снова запросит пароль закрытого ключа.

## Проверьте подпись

```bash
openssl dgst -sha256 -verify signing.pub -signature image.tar.sig image.tar
```

Ожидаются сообщение `Verified OK` и код завершения 0.
Только после успешной проверки загрузите этот архив в Docker:

```bash
docker load -i image.tar
```

## Проверьте обнаружение изменения

Следующая команда создаёт вторую копию архива.
Убедитесь, что на диске достаточно места для копии.

1. Скопируйте архив и измените копию:

   ```bash
   cp image.tar tampered.tar
   printf '\nchanged\n' >> tampered.tar
   ```

2. Проверьте подпись изменённого файла:

   ```bash
   openssl dgst -sha256 -verify signing.pub -signature image.tar.sig tampered.tar
   ```

   Ожидаются ошибка проверки и ненулевой код завершения.
   Не загружайте изменённый архив в Docker.

3. Повторно проверьте исходный архив:

   ```bash
   openssl dgst -sha256 -verify signing.pub -signature image.tar.sig image.tar
   ```

   Снова ожидаются `Verified OK` и код завершения 0.

## Передайте архив получателю

Передайте получателю три файла:

- `image.tar` — архив образа;
- `image.tar.sig` — подпись;
- `signing.pub` — открытый ключ.

Сверьте отпечаток открытого ключа по независимому доверенному каналу.
Если злоумышленник заменит архив, подпись и открытый ключ вместе, простая проверка пройдёт.
Закрытый ключ `signing.key` оставьте у подписанта. Не передавайте его получателю.
Каталоги `demo-*`, ключи и архивы исключены из Git.

Подпись относится к байтам конкретного tar-архива, включая его метаданные.
Другой экспорт того же образа может иметь другие байты.
Для нового архива создайте отдельную подпись.

Это задание не создаёт подпись OCI-образа в Harbor.
Команды `docker run` и `docker load` не проверяют эту подпись автоматически.
Проверяйте архив до загрузки.
Подпись подтверждает целостность архива и происхождение относительно доверенного ключа.
Она не подтверждает отсутствие уязвимостей.
