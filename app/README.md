# Приложение со счётчиком посещений

Приложение принимает HTTP-запросы и считает обращения к пути `/`.
При отдельном запуске оно хранит счётчик в памяти процесса.
При запуске через Compose оно хранит счётчик в Redis.

Нужны Docker с Linux-контейнерами и curl.
Для задания с Redis нужен Docker Compose v2.
Если у вас отдельная команда Compose v2, заменяйте `docker compose` на `docker-compose`.
Порт 8080 должен быть свободен.

Из корня репозитория перейдите в каталог приложения:

```bash
cd app
```

Все команды ниже выполняйте из этого каталога.

## Соберите и запустите образ

1. Соберите образ:

   ```bash
   docker build -t club-demo:1.0 .
   ```

2. Проверьте пользователя контейнера:

   ```bash
   docker run --rm club-demo:1.0 id
   ```

   В выводе должен быть UID `10001`. Приложение работает без прав root.

3. Запустите приложение в фоне:

   ```bash
   docker run -d --name counter-demo -p 127.0.0.1:8080:8080 club-demo:1.0
   ```

4. Проверьте ответы и посмотрите журнал:

   ```bash
   curl http://127.0.0.1:8080/health
   curl http://127.0.0.1:8080/
   docker logs counter-demo
   ```

   Путь `/health` возвращает `{"status":"ok"}`.
   Ответ на запрос `/` содержит число посещений и `"backend":"memory"`.
   После перезапуска процесса счётчик сбрасывается.

В параметре `-p 127.0.0.1:8080:8080` первый порт относится к компьютеру.
Второй порт относится к контейнеру. Доступ разрешён только с этого компьютера.
Инструкция `EXPOSE 8080` в Dockerfile описывает порт, но не открывает доступ к нему.
Параметр `-d` запускает контейнер в фоне.
Если запустить контейнер без `-d`, сочетание `Ctrl+C` остановит приложение.

Перед следующим заданием освободите порт 8080:

```bash
docker stop counter-demo
docker rm counter-demo
```

## Запустите приложение с Redis

1. Проверьте конфигурацию и запустите сервисы:

   ```bash
   docker compose config
   docker compose up -d --build
   docker compose ps
   ```

   Compose запускает приложение после успешной проверки Redis.

2. Дважды обратитесь к приложению и прочитайте счётчик в Redis:

   ```bash
   curl http://127.0.0.1:8080/
   curl http://127.0.0.1:8080/
   docker compose exec redis redis-cli GET visits
   ```

   Ответ приложения содержит `"backend":"redis"`.
   Каждый запрос к `/` увеличивает значение `visits`.

3. Пересоздайте контейнеры и проверьте счётчик:

   ```bash
   docker compose down
   docker compose up -d
   curl http://127.0.0.1:8080/
   ```

   Счётчик продолжает расти. Redis сохраняет данные в журнал AOF в томе `redis-data`.
   Обычная команда `docker compose down` не удаляет этот том.

Если Redis станет недоступен после запуска, запрос `/` вернёт HTTP 503.
Путь `/health` проверяет только HTTP-приложение.
Для проверки связи с Redis используйте путь `/`.

## Остановите сервисы

```bash
docker compose down
```

Чтобы удалить и данные счётчика, используйте `docker compose down -v`.
Эта команда удаляет том `redis-data` и сохранённое значение.

В примере используется учебный сервер Flask.
Для рабочего сервиса нужен WSGI-сервер.
