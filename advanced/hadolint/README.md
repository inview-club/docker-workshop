# Hadolint: плохой и хороший Dockerfile

Нужен запущенный Docker. Выполняйте команды из `advanced/`:

```bash
bash hadolint/lint.sh Dockerfile.bad
bash hadolint/lint.sh Dockerfile.good
```

Плохой пример намеренно завершает проверку с ненулевым кодом:

| Правило | Причина | Что исправить |
| --- | --- | --- |
| DL3007 | `alpine:latest` | Выбрать версию базового образа |
| DL3018 | `apk add curl` без версии пакета | Зафиксировать подходящую версию пакета, если он нужен |
| DL3019 | `apk add` сохраняет кэш | Использовать `apk add --no-cache` |
| DL3025 | `CMD echo hello` запускается через shell | Использовать `CMD ["echo", "hello"]` |

В хорошем примере зафиксирован тег Alpine, используется exec-форма CMD. Установка curl удалена: приложению, которое только печатает hello, этот пакет не нужен. Поэтому предупреждения про apk исчезают за счёт удаления лишней зависимости. Если пакет нужен вашему приложению, исправьте обе настройки apk из таблицы.

Хороший пример должен завершить lint с кодом 0. Это учебная проверка правил Dockerfile; она не заменяет тесты приложения и сканирование CVE. Тег базового образа не гарантирует неизменность содержимого; для этого используют digest.

Скрипт передаёт файл через stdin и не требует bind mount. Для проверки рабочего multistage Dockerfile из `advanced/`:

```bash
docker run --rm -i ghcr.io/hadolint/hadolint:v2.15.1 < multistage/Dockerfile
```
